## 二、功能一：智能记账助手

### 2.1 功能背景

用户在记录消费时，需要手动填写多个字段（金额、分类、日期、成员等），操作繁琐，影响记账效率。

### 2.2 用户场景

| 场景 | 用户输入 | 系统响应 |
|------|----------|----------|
| 场景1 | "中午和老婆吃火锅花了200" | 自动识别：金额200元、分类餐饮-火锅、成员老婆 |
| 场景2 | "昨天打车去机场80块" | 自动识别：日期昨天、分类交通-打车、金额80元 |
| 场景3 | "买了件衣服500" | 自动识别：分类购物-服装、金额500元 |
| 场景4 | "给孩子报了个培训班3000" | 自动识别：分类教育-培训、成员孩子、金额3000元 |
| 场景5 | "今天加油300" | 自动识别：日期今天、分类交通-加油、金额300元 |

### 2.3 功能需求

#### 2.3.1 核心功能

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 金额识别 | 从文本中提取数字金额，支持多种表达方式 | P0 |
| 分类识别 | 根据消费内容推断一级分类和子分类 | P0 |
| 日期识别 | 识别相对日期（今天、昨天、前天）和绝对日期 | P0 |
| 成员识别 | 识别消费参与成员，关联家庭成员 | P1 |
| 时间识别 | 识别消费时间（中午、晚上、12点等） | P1 |
| 描述生成 | 自动生成简洁的消费描述 | P2 |

#### 2.3.2 金额识别规则

支持的表达方式：
- 数字：`200`、`80`、`3000`
- 单位：`200元`、`200块`、`200块钱`、`￥200`
- 口语：`两百`、`三百块`、`一千五`
- 范围：`一百多`、`不到两百`（取中间值）

#### 2.3.3 日期识别规则

| 输入 | 转换结果 |
|------|----------|
| 今天 | 当前日期 |
| 昨天 | 当前日期 - 1天 |
| 前天 | 当前日期 - 2天 |
| 大前天 | 当前日期 - 3天 |
| 本周一 | 本周周一的日期 |
| 上周一 | 上周周一的日期 |
| 5月1号 | 2026-05-01 |
| 5月1日 | 2026-05-01 |

#### 2.3.4 成员识别规则

| 输入 | 关联成员 |
|------|----------|
| 我、自己 | 当前登录用户 |
| 老婆、媳妇、妻子 | 成员"BoBo" |
| 孩子、儿子、女儿 | 需用户确认 |
| 老公、丈夫 | 成员"baorong" |

### 2.4 技术方案

#### 2.4.1 现有接口增强

已有接口：`POST /api/ai/recognize`

增强内容：
```typescript
interface RecognizeResult {
  amount: number | null;           // 金额
  category: string | null;         // 一级分类
  subcategory: string | null;      // 子分类
  date: string | null;             // 日期 YYYY-MM-DD
  time: string | null;             // 时间 HH:mm
  members: string[];               // 成员名称数组
  description: string;             // 描述
  confidence: number;              // 置信度 0-1
  
  // 新增字段
  category_id: number | null;      // 分类ID（用于直接关联）
  member_ids: number[];            // 成员ID数组
  suggestions?: Suggestion[];      // 多个候选建议
}

interface Suggestion {
  category_id: number;
  category_name: string;
  subcategory_name: string;
  confidence: number;
}
```

#### 2.4.2 提示词优化

```
你是消费信息提取助手。从用户输入中提取以下信息：

1. 金额：识别数字金额，支持"200元"、"200块"、"两百"等格式
2. 日期：识别日期表达，"今天"转换为当前日期，"昨天"为当前日期-1天
3. 时间：识别时间表达，如"中午"转换为12:00，"晚上"转换为18:00
4. 分类：根据消费内容推断分类，返回分类ID和名称
5. 成员：识别参与人员，返回成员名称数组

当前日期：{current_date}
当前时间：{current_time}
家庭成员：{members}
分类体系：{categories}

输出JSON格式...
```

## 三、功能二：预算智能建议

### 3.1 功能背景

用户在设置月度预算时，往往不清楚应该设置多少，缺乏历史数据参考。

### 3.2 用户场景

| 场景 | 用户操作 | 系统响应 |
|------|----------|----------|
| 场景1 | 进入预算设置页面 | 显示"获取AI建议"按钮 |
| 场景2 | 点击"获取AI建议" | 分析历史数据，推荐预算方案 |
| 场景3 | 查看建议 | 显示总预算和各分类预算建议 |
| 场景4 | 采纳建议 | 一键应用推荐的预算设置 |

### 3.3 功能需求

#### 3.3.1 核心功能

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 总预算建议 | 根据历史消费推荐月度总预算 | P0 |
| 分类预算建议 | 为每个消费分类推荐预算 | P0 |
| 趋势调整 | 考虑消费趋势调整建议 | P1 |
| 一键应用 | 将建议直接应用到预算设置 | P1 |

#### 3.3.2 建议算法

```
1. 获取过去3个月消费数据
2. 计算各分类月均消费
3. 分析消费趋势（上升/下降/稳定）
4. 根据趋势调整建议值：
   - 上升趋势：月均 * 1.1
   - 下降趋势：月均 * 0.9
   - 稳定：月均
5. 汇总各分类得到总预算建议
```

### 3.4 技术方案

#### 3.4.1 新增API

```

请求体：
{
  "months": 3  // 分析最近几个月的数据
}

响应体：
{
  "success": true,
  "data": {
    "total_budget": 6000,
    "category_budgets": [
      { "category_id": 1, "category_name": "餐饮", "suggested_budget": 1500, "avg_spent": 1400, "trend": "stable" },
      { "category_id": 2, "category_name": "交通", "suggested_budget": 500, "avg_spent": 450, "trend": "up" },
      ...
    ],
    "analysis_summary": "根据过去3个月消费数据，建议月度预算6000元...",
    "confidence": 0.85
  }
}
```

#### 3.4.2 提示词设计

```
你是家庭财务顾问。根据用户过去几个月的消费数据，提供预算建议。

分析要点：
1. 计算各分类月均消费
2. 识别消费趋势
3. 考虑季节性因素
4. 提供合理的预算建议

输出JSON格式：
{
  "total_budget": 总预算建议,
  "category_budgets": [
    {
      "category": "分类名",
      "suggested_budget": 建议预算,
      "avg_spent": 月均消费,
      "trend": "up/down/stable",
      "reason": "建议理由"
    }
  ],
  "analysis_summary": "整体分析说明",
  "tips": ["节省建议1", "节省建议2"]
}
```

## 四、功能三：智能搜索

### 4.1 功能背景

用户想查找特定消费记录时，需要手动筛选或翻阅历史，效率低下。

### 4.2 用户场景

| 场景 | 用户输入 | 系统响应 |
|------|----------|----------|
| 场景1 | "上个月吃的火锅" | 返回上个月分类为火锅的消费记录 |
| 场景2 | "最近打车花了多少" | 汇总最近打车消费总额 |
| 场景3 | "给老婆买的东西" | 返回成员为老婆的购物记录 |
| 场景4 | "超过500的消费" | 返回金额大于500的消费记录 |
| 场景5 | "上周六的消费" | 返回上周六的所有消费记录 |

### 4.3 功能需求

#### 4.3.1 核心功能

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 自然语言解析 | 理解用户搜索意图 | P0 |
| 多条件组合 | 支持日期、金额、分类、成员等条件 | P0 |
| 智能汇总 | 对搜索结果进行统计分析 | P1 |
| 结果排序 | 按相关性或时间排序 | P1 |

#### 4.3.2 支持的查询类型

| 查询类型 | 示例 |
|----------|------|
| 按分类 | "火锅消费"、"打车记录" |
| 按时间 | "上周的消费"、"5月份的支出" |
| 按金额 | "超过100的"、"100到500之间" |
| 按成员 | "我花的钱"、"给老婆买的" |
| 组合查询 | "上个月超过200的餐饮消费" |
| 统计查询 | "最近打车花了多少"、"这个月吃了多少次火锅" |

### 4.4 技术方案

#### 4.4.1 新增API

```
POST /api/ai/search

请求体：
{
  "query": "上个月吃的火锅",
  "limit": 20
}

响应体：
{
  "success": true,
  "data": {
    "parsed_query": {
      "date_range": { "start": "2026-04-01", "end": "2026-04-30" },
      "category": "火锅",
      "amount_range": null,
      "member": null
    },
    "results": [
      { "id": 1, "amount": 200, "date": "2026-04-15", "description": "火锅" },
      ...
    ],
    "summary": {
      "total_count": 3,
      "total_amount": 650,
      "avg_amount": 216.67
    },
    "answer": "上个月您吃了3次火锅，共消费650元"
  }
}
```

#### 4.4.2 提示词设计

```
你是消费记录搜索助手。解析用户的自然语言查询，提取搜索条件。

支持的查询条件：
- date_range: 日期范围
- category: 分类名称
- subcategory: 子分类名称
- member: 成员名称
- amount_min: 最小金额
- amount_max: 最大金额
- keywords: 关键词

输出JSON格式：
{
  "parsed_conditions": {
    "date_range": { "start": "YYYY-MM-DD", "end": "YYYY-MM-DD" },
    "category": "分类名或null",
    "member": "成员名或null",
    "amount_min": 数字或null,
    "amount_max": 数字或null
  },
  "query_type": "list/summary",
  "natural_answer": "自然语言回答"
}
```
